Resource: Case II bathroom object graphics
Resource ID: $81
Bank $32, entry $01 at $4002

Region  CPU range (inclusive)  ROM offset  Stored bytes
US      $4273-$4598            $0C8273      806
JP      $4273-$4598            $0C8273      806

Source ROMs: asm/<region>/game.gbc
Editable source: res/shared/gfx/case2_bathroom_object_tiles.png
ROM blocks: res/<region>/gfx/case2_bathroom_object_tiles.bin

Both regions contain identical bytes. Header $1C $00 $40 describes 64
8x8 2bpp tiles (1024 decoded bytes). The compressed stream ends exactly
at pointer entry $02, $4599. The shared PNG arranges the tiles in 16
columns and uses grayscale to preserve the four color indices. Object
color zero is transparent when rendered as a hardware sprite; the atlas
shows it as white so the tile pixels remain editable.

Loading and display
-------------------
Scene $00's graphics pair at US $01:$47E5 / JP $01:$47DA is $02 $81.
The second ID is copied into $FFA5. US $00:$0B32 / JP $00:$0B27 resolves
the ID, decompresses into WRAM bank 2 at $D000, and transfers the staged
data to VRAM bank 0 at $8000. ID $81 resolves as Case II base bank $2A
plus upper nibble $08, using the low nibble $01 in the bank-local table.
The resource's tiles occupy $8000-$83FF (sprite tile IDs $00-$3F).

Both $0C and $0D compression families call the same decoder at $0680.
Bit zero controls the direct-VRAM destination adjustment for signed BG
addressing. Resource $1C does not apply that BG adjustment. gb_lz.py now
accepts $0C/$0D and their $10 variants while preserving original headers.

The sprite writer at bank zero $04B3 reads a part count followed by
relative Y, relative X, tile ID, and attribute bytes for each part.
It adds the object's position from HRAM $FF93/$FF92 and the hardware
offsets of 16/8, then emits OAM records into $C000. It stops at 40 OAM
entries, clips off-screen coordinates, and skips tile ID $FF.

US $18AA selects common sprite definitions through bank $02:$400A.
US $18C1 selects case-specific definitions; the Case II pointer table
is at bank $02:$4B7A, dispatched through $5F4F. Definition records choose
the tile arrangement and attributes. A tile atlas alone does not encode
which object is visible or where it is placed in the current scene.

Object palette
--------------
Shared source: res/shared/palettes/case2_bathroom_objects.pal
Bank $0B, CPU $5430-$546F, ROM offset $02D430, 64 bytes

US $1933 / JP $1A83 loads the object palette. Its Case II bank/table
selectors are US $1A11/$1A13 and JP $1B61/$1B63: bank $0B, table $5398.
Scene index $00 points to $5430. The loader copies eight palettes of
four little-endian RGB555 colors to $DC00; bank $01 copies them through
the active palette buffers and uploads object colors. The shared file
preserves all 64 bytes, including each palette's transparent color slot.

ASM and editing
---------------
Both bank_032.asm files declare the resource pointers as words; entry
$01 uses Case2BathroomObjectTiles. INCBIN slices preserve existing labels.
Both bank_00b.asm files include the shared palette, retaining its labels.
The Makefiles rebuild each compressed block from the shared indexed PNG
and include the graphics/palette as game.o dependencies.

Edits must keep 64 tiles and fit the original 806-byte compressed slot.
Unchanged pixels preserve the original stream. The palette must remain
64 bytes. Generated .2bpp files stay beside each regional output.

The bathroom background previews retain their door-state behavior.
Game-derived content retains the rights described in LICENSE. No new
dependency was added.

Scene objects and initial visibility
------------------------------------
The following records are identical in US and JP. They are shared files
under res/shared/objects/ and are included by both regional ASM sources.

File                         Bank:CPU range   Bytes
case2_bathroom.hitboxes       $05:$4A13-$4A60  78
case2_bathroom.positions      $02:$7366-$736F  10
case2_bathroom.animations     $02:$5CCF-$5CE7  25
case2_bathroom.sprites        $02:$4C88-$4CF8  113
case2_initial_flags.bin       $03:$4196-$41ED  88

The Case II room pointer table starts at $05:$48D1. Room $00 points to
$4A13. Each hitbox record is seven bytes: left, right, top, bottom,
type/flags, name index, and object index. A single $FF ends the room list.
The $80 bit in type/flags enables an object sprite. Only records for
objects $00-$04 have that bit set in this room; the other records are
interaction areas without a sprite. These records also preserve the
original name indices, without assigning names from the tile atlas.

US $00:$0EE0 scans these room records. $02:$6BF4 immediately returns in
Case II; its special object substitutions apply to Case I. $02:$7267
checks two flags for each object: presence in $C420 and visibility in
$C438. $02:$7289 appends its X, Y, and object index to $C600. Positions
come from the Case II table at $7366, indexed by object ID.

Case II initialization at $03:$40BC fills $C420 with $FF, clears $C438,
and calls $4174 to set the visibility flags listed at $4196. That list
contains $00, $01, and $02, but does not contain $03 or $04. The resulting
bathroom OAM order and screen positions, with scroll $C197 = zero, are:

Object  X   Y   Animation  Sprite   Parts  Initial state
$00     78  45  $5CCF      $4C88    4      visible
$01     41  23  $5CD4      $4C99    10     visible
$02     57  23  $5CD9      $4CC2    8      visible
$03     105 22  $5CDE      $4CE3    2      hidden
$04     16  61  $5CE3      $4CEC    3      hidden

The first five pointers at $02:$5BC9 select these five animations. Each
is $FE, sprite index, $FF, $FF, $00: a static initial sprite. $02:$60C7
reads the initial sprite index, then the writer reached through US
$18D8 / bank $02:$5F69 resolves it through $02:$4B7A. The first five
entries now name Case2BathroomSprite00 through Case2BathroomSprite04.
Their records contain a count followed by relative Y/X, tile, attribute.

$02:$7446 draws the $C600 list, subtracting $C197 from each object's Y.
The three visible objects emit 22 OAM entries and use tile IDs $00-$15.
The preview follows the writer's coordinate wrapping, $A8/$B0 clipping,
tile-$FF skip, and 40-entry limit. It renders 8x8 bank-zero sprites,
transparent color zero, palette selection, flips, first-OAM priority,
the ten-sprites-per-scanline limit, and background priority for nonzero
background colors. The current bathroom uses at most six entries on
any scanline. The image contains the scene rectangle only, without HUD,
cursor, dialogue window, or startup animation frames.

Preview
-------
Run from the repository root:

    make bathroom-objects-preview

This target processes resources only. It writes the 112x112 preview
case2_bathroom_objects.png to the system temporary directory and prints
its path. It uses the closed door and new-game visible object set.
Only case2_bathroom.png, the main background preview, stays in
res/shared/tilemaps.

Render the initial objects or the open-door variant on demand with:

    python scripts/bathroom_preview.py res/US --objects
    python scripts/bathroom_preview.py res/US --objects --door open

Both commands write to the temporary directory. Use --output PATH to choose
an output file explicitly. These previews do not load a save file or display
the inventory and dialogue UI.

Use res/JP to render with the Japanese graphics resources. Position,
animation, sprite, hitbox, and initial flag edits remain fixed-size so
their ASM slots and following table entries keep the same addresses.

Towel pickup state
------------------
The name mapping at US $01:$64EA uses base $00 for category $03 and base
$70 for category $04. The room hitboxes therefore identify object $00 as
NAME:$05, TOWEL; object $01 as NAME:$70, TRENCH COAT; and object $02 as
NAME:$71, PANTS. These names come from the extracted object-name table.
Objects $03 and $04 show the broken mirror and running water. Their
script conditions are documented below. Their graphics stay in the object tile atlas.

The Case II inventory action table is at US $07:$5591. Entry $05 points
to $5671; action dispatch $02:$6CB4 maps command index $02 to script slot
$03, whose pointer at $5677 selects the towel's pickup script. The JP
table, action-list pointer, and script pointer are each two bytes later.

Region  Script CPU range  Pointer   Bytes
US      $07:$6024-$602E   $5677     11
JP      $07:$6026-$6030   $5679     11

Regional source: res/<region>/scripts/case2_bathroom_towel_take.bin
ASM symbol: Case2BathroomTowelTake

US script bytes: $17 $E0 $66 $05 $DA $66 $2A $00 $07 $DE $66
JP script bytes: $17 $E2 $66 $05 $DC $66 $2A $00 $07 $E0 $66

The regional branch addresses differ. Both scripts contain $2A $00,
which clears visibility for scene object $00. The Case II interpreter
at US $00:$39BB uses the command table at $39E0. Opcode $2A dispatches
to $2616: it reads an object ID, selects the $C438 flag bitmap, and clears
that bit. The successful path then branches to US $07:$66DE / JP $07:$66E0,
where $26 invokes the common pickup routine. The routine updates inventory
and redraws the scene through US $00:$2666. The $C420 presence flag stays
set; $C438 visibility is sufficient to remove the sprite from the room.

The visibility change is recorded as script data. No pickup-state background
preview is generated. The towel graphics remain in the object tile atlas.

Hidden objects: broken mirror and running water
-----------------------------------------------
Object $03 is the broken-mirror overlay at (105,22). Room interaction
index $03 resolves through $07:$4006 to the action list at $4172 (US).
Its third pointer, at $4176, selects $4C2F. The script is:

    28 03       Test object $03 visibility in $C438.
    03 21 47    If already visible, branch to $4721 (already broken).
    3E 13       Play sound $13.
    29 03       Set object $03 visibility.
    2B          Redraw the scene.
    30 AE       Set the message object name to MIRROR.
    2C 00       Display the generic object-broke message.
    FF          End.

The repeat branch at $4721 uses name $AD (GLASS) and generic message $01
(already broken). The examine script at $46ED tests the same visibility
bit and skips the intact-mirror reflection sequence after it is set.
JP's break script starts at $4C31; all 15 bytes match US, including the
shared $4721 branch destination. This is an interaction-driven overlay,
independent of the bathroom door patches.

Object $04 is running water at (16,61). Room interaction indices $01/$02
resolve to action lists $4162/$416A. Their open-script pointers at
$4164/$416C select $4D47/$4D58. The scripts name COLD TAP ($D2) and HOT
TAP ($D3), respectively. The corresponding examine scripts name BLUE
($B2) and RED ($B1) in the generic faucet description.

The tap state uses bits $01 (cold) and $02 (hot) in $C450, separate from
the sprite visibility bitmap at $C438. Opcode $08 branches when a state
bit is set; $54 branches when it is clear; $09 sets it and $0A clears it.
Opcode $29 sets sprite visibility, $2A clears it, and $2B redraws.

Action         US script  JP script  Visibility change
Open cold      $4D47      $4D49      Set $04; set cold bit $01.
Open hot       $4D58      $4D5A      Set $04; set hot bit $02.
Close cold     $4DD3      $4DD5      Clear $04 only if hot bit $02 is clear.
Close hot      $4DEA      $4DEC      Clear $04 only if cold bit $01 is clear.

Opening an already open tap branches to the generic already-open message
at US $4D55 / JP $4D57. Closing an already closed tap branches to the
already-closed message at US $4E1F / JP $4E21. A successful close clears
its own tap bit whether or not water remains visible. With either tap
open, $04 remains visible; closing the last open tap removes it.

Two further script entries at US $5022/$5041 (JP $5024/$5043) toggle the
cold/hot bits. They contain the same visibility rule: opening sets $04,
and closing clears it only when the other tap is off. Their caller/action
mapping has not yet been traced, so they are not assigned a UI command.

Evidence was checked directly against both local ROMs, the interpreter
handlers, action pointers, and extracted Case II text. The relevant
handlers in US bank zero are $2600/$260A/$2616 for visibility test/set/
clear, $2622 for selecting $C438, and $1D1F for selecting $C450. The
mirror script matches exactly between regions; the tap scripts retain
the same operations with their regional branch addresses. No preview
image or ROM build was generated for this analysis.

Verification
------------
The 12 gb_lz tests passed, covering unchanged and edited $1C resources.
Converting the shared PNG with rgbgfx and rebuilding both regional blocks
retained all 806 original bytes. Static expansion matched the local ROMs
for the bank $32 pointer prefix (66 bytes), graphics splice (1037 bytes),
and bank $0B palette splice (90 bytes). Original labels and the remaining
assembly were preserved. No ROM build verification was run.

The sprite overlay adds eight tests for transparency, flips, palettes,
sprite/background priority, scanline selection, partial clipping, writer
limits, and initial bathroom selection. All eight passed, along with
the existing 16 tilemap tests. Base, closed, and open object previews
match between US and JP. Static expansion of each new ASM replacement
matched the corresponding local ROM bytes; all original labels were
retained, including $05:$48D2 inside the room pointer word. LOW/HIGH
expressions preserve that label while naming the pointer. Source edits
outside these data blocks only replace address literals with symbols.

The object-state preview presets and their tests were removed. The
remaining sprite tests cover rendering and initial scene selection.
