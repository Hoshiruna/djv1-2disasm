Resource: Case II font and HUD graphics
ROM bank: $2A
Pointer table: $4000; font entry $00 at $4000, HUD entry $01 at $4002

Region  Resource  CPU range (inclusive)  ROM offset  Stored bytes
US      Font      $4020-$4397            $0A8020      888
US      HUD       $4398-$48B2            $0A8398     1307
JP      Font      $4020-$453E            $0A8020     1311
JP      HUD       $453F-$4A59            $0A853F     1307

Sources: asm/US/game.gbc and asm/JP/game.gbc
Exports: res/<region>/gfx/case2_font.bin and case2_hud_tiles.bin
Editable images (16 columns):
US font: res/US/gfx/font.png, shared by Case I and Case II
JP font: res/JP/gfx/case2_font.png
JP Case I font: res/JP/gfx/case1_font.png (bank $33)
HUD: res/<region>/gfx/case2_hud_tiles.png

Both resources use the existing gb_lz codec and decode to 2048 bytes,
or 128 8x8 2bpp tiles. Each compressed stream ends at the next pointer.
The font header is $1D $80 $80; the HUD header is $1D $00 $80.
The loader places the font at $8800 (IDs $80-$FF) and the HUD at $9000
(IDs $00-$7F). Case I HUD graphics contain only 112 tiles, IDs $10-$7F.

Loading path
------------
WRAM $C599 selects the case: zero uses bank $33, nonzero uses bank $2A.
US Call_000_0a36 and JP Call_000_0a2b read the font pointer at $4000.
US Call_000_0a5b and JP Call_000_0a50 read the HUD pointer at $4002.
Both paths pass the selected resource to Call_000_050c.

The US font decodes identically to Case I. Editing font.png updates both
US cases, with separate .bin files retaining each ROM slot and header.
The JP font has six different tile readings, documented in resource-text.txt,
so its two cases keep separate editable PNGs. HUD images remain separate
because their tile data and counts differ between cases.

The PNGs use palette 7 from the existing hud.pal for editing previews.
This does not identify the runtime palette of every Case II screen.
Embedded palette indices preserve the original 2bpp color IDs.

ASM and editing
---------------
Both bank_02a.asm files now declare the 16 resource pointers as words.
Entries $00/$01 use symbolic labels. INCBIN slices retain all original
labels within the extracted resources. Bytes from resource $02 up to
the next original label remain inline; later assembly is unchanged.

The regional Makefiles include both resources as game.o dependencies.
Their existing PNG rule calls rebuild_gfx.py and rgbgfx --colors embedded.
US case2_font.bin has an explicit rule using the shared font.png.
The converter writes intermediate .2bpp files beside each output .bin,
so resources sharing a PNG can be converted independently.
The codec preserves unchanged compressed bytes, headers, and slot sizes.
Edits must retain 128 tiles and fit the original compressed space.
The clean target removes the generated Case II .2bpp files.

Game-derived graphics retain the rights described in LICENSE.

Verification
------------
The PNG sources were converted with rgbgfx --colors embedded and matched
all four decoded resources byte for byte. The 11 gb_lz tests passed,
including unchanged and edited Case II resource round-trips.
Static expansion of the modified ASM prefixes matched the local ROMs
(US: 2350 bytes; JP: 2755 bytes). All original labels were retained at
their recorded addresses, and the remaining assembly text was unchanged.
This checks the extracted ranges, not the provenance of the local ROMs.
No ROM build verification was run.
