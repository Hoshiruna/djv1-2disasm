Resource: Case II scene $01 tile export

The scene graphics pair at US $01:$47E7 / JP $01:$47DC is $04 $82.
This phase exports tile atlases only. Scene $01 is a numeric identifier;
its location name has not been assigned. No background state preview or
new ROM build dependency is introduced.

Exported files
--------------
res/shared/gfx/case2_scene01_tiles.png
    Background resource $04, header $1D $00 $74.
    1856 decoded bytes; 29 columns x 4 rows of 8x8 tiles (232x32 pixels).
    The layout contains exactly 116 tiles without padding.

res/shared/gfx/case2_object82_tiles.png
    Object resource $82, header $1C $00 $40.
    1024 decoded bytes; 16 columns x 4 rows of 8x8 tiles (128x32 pixels).
    The same resource is selected by multiple scenes, so its filename
    uses the resource ID rather than a single scene name.

Both resources have identical compressed bytes and decoded pixels in
US and JP. Each PNG is shared between regions, uses indexed colors 0-3,
and displays those indices as white, light gray, dark gray, and black.
These grays are editing colors, not the game's runtime palettes.
Object index zero stays visible in the atlas to preserve its tile data.

The background loader also requests resource $05. It is a single $FF
byte at US $2A:$5583 / JP $2A:$572A, with no tile payload to export.

Validation
----------
Both compressed streams finish exactly at the next resource pointer.
Rebuilding unchanged decoded data with gb_lz.rebuild_resource preserves
the complete original blocks. Reading the saved PNG indices back into
2bpp planes reproduces every decoded byte, including tile order. The
atlases were also visually inspected. No ROM build was run.

The bank assembly still contains these original resource blocks. These
PNGs are exports; edits to them are not yet connected to ROM rebuilding.
Game-derived graphics retain the rights described in LICENSE.

Each file contains eight palettes of four little-endian RGB555 words.
Bits 0-4 are red, 5-9 green, and 10-14 blue. The background pointer table
is at $0B:$4000; the object pointer table is at $0B:$5398. Both are indexed
by scene for the ordinary scene palette path. Special runtime palette
changes are outside this export.

The atlases retain color indices 0-3. A background cell's attribute byte
selects its palette using bits 0-2; an object's OAM attribute does the same
for object palettes. Object color index zero is transparent when drawn.
A shared object atlas can therefore have different colors in each scene.
The .pal files preserve every original color, including index-zero entries.

Palette selection is not implied by atlas order: apply palettes using the map/OAM attributes when reconstructing a
scene. These palette files are exports and are not yet included by ASM.
Readback matched both original ROMs byte for byte; all 32 words per file
fit RGB555. No ROM build verification was run.
