Loading path
------------
WRAM $C599 selects the case; $C522 selects the scene. The scene graphics
routine uses a two-pointer table at US $01:$46AF / JP $01:$46A4.
Its Case II table is at US $01:$47E5 / JP $01:$47DA. Scene index $00
starts with $02 $81, copied to HRAM $FFA4/$FFA5.

US $00:$0A76 / JP $00:$0A6B checks the cached graphics IDs. For the
background ID in $FFA4, US $0ACC / JP $0AC1 loads that resource and
the next one. Thus this scene uses $02 together with $03.

US $0AA7 / JP $0A9C resolves an ID: its upper nibble is added to the
case's base bank ($33 or $2A), and its lower nibble indexes the word
table at $4000. The base-bank bytes are at US $0ACA / JP $0ABF.
ID $02 in Case II therefore selects bank $2A, pointer $4004.

US $0B62/$0B7E and JP $0B57/$0B73 dispatch the graphics header and
decompress into WRAM bank 2. Header $1D $00 $80 selects the existing
compressed-tile format, destination $D000, and 128 tiles (2048 bytes).
The scene loader later transfers the staged background graphics to VRAM
bank 1, starting at $9000. Resource $03 has header $1D $80 $22, which
loads 34 tiles (544 bytes) into WRAM $D800. The later transfer places
these tiles at VRAM bank 1, $8800-$8A1F (signed BG IDs $80-$A1).

Editing and integration
-----------------------
Edit the shared PNG to change both versions. Each regional Makefile
uses rebuild_gfx.py with its own compressed block as the size/header
template. Generated .2bpp files sit beside the output .bin so parallel
regional conversions do not share an intermediate file.

The original compressed stream consumes all 1545 stored bytes. Edits
must keep 128 tiles and compress into that space. Unchanged pixels keep
the original compressed bytes. Both ASM files use Case2BathroomTiles
for pointer $02 and retain existing address labels with INCBIN slices.
Resource $03 uses Case2BathroomExtraTiles and the same sliced INCBIN
approach. Its compressed stream fills its 349-byte slot; edits must keep
34 tiles and fit that space. Bytes before the next label in resource $04
remain inline. Both resources are dependencies of each regional game.o.

Game-derived graphics retain the rights described in LICENSE. No new
dependencies or codecs were added. No ROM build verification was run.

Door state patches
------------------
Bank $29 contains two identical regional patches for the bathroom door:

State   Index  CPU range     ROM offset  Size
Closed  $00    $4114-$4156   $0A4114     67 bytes
Open    $01    $4157-$4199   $0A4157     67 bytes

Each patch starts with $2F $04 $08, followed by eight rows of four tile
IDs and four attributes. The position pairs at $29:$6758/$675A are both
$05 $02, placing the patch at column 5, row 2 of the 14x14 scene.
The replacement routine at $29:$66BB writes tile IDs and attributes
into the interleaved WRAM map, advancing 14 bytes between row planes.

The room-zero record at $03:$479B is $20 $00 $02 $00, then $FF. Bank 3
$4236 chooses patch $00 or $01 according to object flag $00. New-game
initialization clears the object flag block at $C420-$C59F, and the
initial flag list at $03:$4138 does not set $00, so the door starts closed.
The closed patch matches the original base map rectangle exactly.
The open patch changes 32 tile IDs and 25 attributes.

The open patch uses tile $FF. Startup menu resource $03 in bank $09
(US $5777, JP $56CC) has header $1D $80 $80 and a zero-filled final tile.
Call_000_09D4 (US) loads that menu graphics pair before gameplay. The
background staging bank retains the blank final tile when bathroom
resources $02/$03 replace only the first 162 tiles. The preview supplies
that confirmed blank tile as sixteen zero bytes.
